# P42 — reusable unlisted participant-page system

Implemented a dedicated `participantPages` content collection with exact validated
`route_path` values and collision checks, plus a shell-preserving renderer.
Ordered blocks support rich text, action groups, multiple local images, and
independent Radix/shadcn Accordion groups. Every participant page passes `noindex`
to the shared layout, which emits `noindex, nofollow`; participant entries are
never consumed by listings, feeds, admin retrieval or sitemap generation.

Courtesy codes use only a salted SHA-256 digest in frontmatter and browser-side
comparison. All resources are hidden until success; successful access is retained
in sessionStorage and focuses the page heading. This is obscurity and a courtesy
gate, not authentication or server-side security. Static assets must contain no
confidential data.

Director acceptance evidence (2026-09-28):

- `pnpm p42:validate` passed.
- `pnpm check` passed with 0 errors and 0 warnings (two non-blocking script hints).
- A temporary fixture built successfully at both `/` and `/aiindeklas/`.
- `pnpm p42:fixture /` and `pnpm p42:fixture /aiindeklas/` proved the route
  carried `noindex, nofollow`, preserved ordered blocks, used base-safe internal
  links and images, omitted the plaintext test code, and was absent from the
  sitemap, feeds, admin retrieval and public home output.
- `pnpm p42:browser /` and `pnpm p42:browser /aiindeklas/` proved resources were
  initially hidden and unfocusable, an incorrect code stayed locked, the correct
  code revealed content and focused the page heading, session-only restoration
  worked, the Accordion opened from the keyboard, and the mobile viewport did
  not overflow.

The test-only fixture was removed after verification. P42 therefore ships the
reusable system and authoring guidance, but no participant content page. Its
courtesy gate remains deliberately documented as obscurity rather than secure
authentication; static assets must never contain confidential data.

Director integration review also removed a duplicate hidden H1 and now removes
the complete gate shell after successful entry. A gated page keeps one visible
page H1 throughout while all participant resources remain hidden until access.
